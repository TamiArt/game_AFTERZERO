# Подключение AFTERZERO к Telegram Mini App

Эта инструкция рассчитана на рабочую ветку `chore/afterzero-audit-roadmap`. Приложение использует официальный Telegram Web Apps SDK, серверную проверку `initData`, JWT-сессию и PostgreSQL для сохранения мира.

## Что нужно до подключения

- HTTPS-адрес фронтенда, который стабильно открывается без входа в аккаунт хостинга.
- HTTPS-адрес API, доступный из Telegram.
- PostgreSQL с применёнными Prisma migrations.
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Токен бота. Храни его только в секретах хостинга API; не вставляй в frontend, GitHub-файлы или переписку.

> Важно: локальный/demo-режим сохраняет состояние только в браузере. Для постоянного прогресса между устройствами и запусками нужен работающий API и база данных. Если API настроен, но Telegram-авторизация не прошла, игра теперь не переключается молча в demo-режим.

## 1. Размести фронтенд

Разверни ветку `chore/afterzero-audit-roadmap` на HTTPS-хостинге статического frontend (например, Vercel).

Добавь переменную окружения frontend **до сборки**:

```env
VITE_API_URL=https://YOUR-API-HOST/api/v1
```

Заменяй `https://YOUR-API-HOST` на реальный адрес API без завершающего слеша. После изменения переменной требуется новая сборка. Фронтенд не должен содержать Telegram bot token, `DATABASE_URL` или `JWT_SECRET`.

## 2. Размести API и базу данных

API — отдельный Node.js/NestJS-сервис, а не статические файлы frontend. Выбери хостинг, поддерживающий Node.js 22, запуск долгоживущего HTTP-сервера и переменные окружения; PostgreSQL может быть на том же или отдельном провайдере.

Для API задай секретные переменные:

```env
NODE_ENV=production
API_PORT=3000
WEB_APP_ORIGIN=https://YOUR-FRONTEND-DOMAIN
DATABASE_URL=YOUR_POSTGRESQL_CONNECTION_STRING
TELEGRAM_BOT_TOKEN=YOUR_BOTFATHER_TOKEN
JWT_SECRET=YOUR_RANDOM_SECRET_AT_LEAST_32_CHARACTERS
```

- `WEB_APP_ORIGIN` — только origin фронтенда: схема + домен, без пути и завершающего слеша.
- `DATABASE_URL` — строка подключения к PostgreSQL от провайдера; используй рекомендованные им SSL-параметры.
- `JWT_SECRET` — уникальный случайный секрет минимум 32 символа. Не используй пример из репозитория.
- `TELEGRAM_BOT_TOKEN` — токен именно того бота, через который будет запускаться игра.

Команды сборки и запуска из корня репозитория:

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm db:migrate:deploy
pnpm api:start
```

В настройках платформы укажи `pnpm db:migrate:deploy` как release/deploy command, если платформа поддерживает отдельную команду миграций. API слушает `API_PORT` (по умолчанию 3000) и публикует endpoints под `/api/v1`.

После запуска проверь:

- `https://YOUR-API-HOST/api/v1/health/live` — ожидается HTTP 200.
- `https://YOUR-API-HOST/api/v1/health/ready` — ожидается HTTP 200 с `database: "up"`.

Не добавляй `VITE_API_URL` в окружение API вместо frontend и не выставляй токен бота в переменные с префиксом `VITE_`.

## 3. Настрой бота в BotFather

1. Открой [@BotFather](https://t.me/BotFather) и выбери нужного бота.
2. Выполни `/setmenubutton`, выбери бота, задай название кнопки, например `Играть`, и вставь HTTPS-адрес фронтенда.
3. Если используешь настройку Mini App через меню Web App, укажи тот же HTTPS-адрес. Команды BotFather могут отличаться в зависимости от выбранного способа запуска.
4. При необходимости настрой короткое описание и картинку приложения отдельно — они не влияют на авторизацию.
5. Открой бота в Telegram и нажми кнопку запуска. Не тестируй production-авторизацию простым открытием URL в обычной вкладке браузера: там нет доверенного Telegram `initData`.

## 4. Проверка после подключения

- Mini App открывается внутри Telegram и занимает доступную высоту экрана.
- При первом входе API принимает `initData`, проверяет подпись и создаёт/находит игрока.
- `GET /api/v1/health/ready` подтверждает подключение к БД.
- Перезагрузка Mini App возвращает сохранённый мир того же Telegram-пользователя.
- Если API или Telegram-авторизация недоступны, показывается экран подключения/ошибки, а не игровое состояние, которое может выглядеть как сохранённое.
- В браузере разработчика проверь отсутствие CORS-ошибок. Origin должен совпадать с `WEB_APP_ORIGIN` посимвольно.

## Что нельзя настроить из исходного кода за тебя

Для окончательного запуска нужны значения, которые доступны только владельцу инфраструктуры: домен фронтенда, публичный адрес API, строка PostgreSQL и bot token из BotFather. Не коммить эти значения в репозиторий и не отправляй bot token в чат. После публикации HTTPS-адреса фронтенда его можно добавить в BotFather.
